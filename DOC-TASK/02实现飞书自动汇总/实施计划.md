# 飞书自动汇总实施计划

## 目标

在现有微信 AI Bot 项目中增加飞书自动汇总能力。先以 `instances/tsja` 作为开发和测试对象，验证稳定后再复制配置到 `instances/wife`。

最终效果：

- 每一轮聊天写入飞书多维表格。
- 一轮聊天定义为：用户发出一次有效请求，机器人返回一次 AI 回复。
- 多维表格用于结构化记录和检索。
- 每天 20:00 生成当日聊天简报。
- 多维表格和每日总结云文档统一放在飞书云盘的 `Chatbox` 文件夹下。
- `tsja` 和 `wife` 使用不同飞书账号，通过 `lark-cli --profile` 区分。

## 现状

项目当前结构：

- `bot.js` 是所有实例共享的主程序。
- `instances/tsja/config.json` 是 TSJA 实例配置。
- `instances/wife/config.json` 是 wife 实例配置。
- PM2 通过不同 `cwd` 启动不同实例。
- `sendAiReply()` 是一轮 AI 对话最合适的汇总接入点。
- 当前 `callAI()` 会累计每日 token 到 `dailyStats`，但没有按单轮返回 token 用量。
- 文件上传后会解析为文字，暂存在 `pendingFiles`，并在用户下一条请求时合并进模型输入。
- 已安装并验证 `lark-cli version 1.0.48`。
- 已验证当前账号可以搜索和读取飞书云文档。
- 已确认 `lark-cli` 支持多 profile，用于多飞书账号隔离。

## 总体方案

采用“多维表格 + 云文档/日报”的组合。

多维表格记录每轮原始对话和元数据，方便检索、筛选、统计。

日报由 Deepseek 生成，适合给人快速阅读。日报可以先写入多维表格的日报表，后续再扩展为写入云文档。

所有飞书侧产物必须归档在当前账号飞书云盘的 `Chatbox` 文件夹下：

- 聊天记录多维表格放在 `Chatbox` 文件夹下。
- 每日总结云文档放在 `Chatbox` 文件夹下。
- TSJA 和 wife 是不同飞书账号，因此各自账号下都需要有自己的 `Chatbox` 文件夹。
- 自动化配置中应保存 `Chatbox` 文件夹 token，避免写入云盘根目录或错误目录。

第一阶段优先保证每轮聊天稳定入库；第二阶段再实现每日 20:00 简报。

## 多维表格字段设计

字段排序必须优先满足人工查看体验。前四个字段固定为：

1. 摘要
2. 时间
3. 用户内容
4. AI回复内容

完整字段建议如下：

| 顺序 | 字段名 | 类型建议 | 说明 |
|---:|---|---|---|
| 1 | 摘要 | 文本/标题 | Deepseek-v4-flash 生成，20 字以内 |
| 2 | 时间 | 日期时间 | 本轮对话发生时间，Asia/Shanghai |
| 3 | 用户内容 | 多行文本 | 用户本轮发出的有效内容 |
| 4 | AI回复内容 | 多行文本 | AI 返回给用户的内容 |
| 5 | 附件内容 | 多行文本 | 本轮对话涉及的文件解析文本 |
| 6 | 附件名称 | 文本 | 多个文件用换行分隔 |
| 7 | 输入Token | 数字 | 本轮 input token |
| 8 | 输出Token | 数字 | 本轮 output token |
| 9 | 总Token | 数字 | 输入Token + 输出Token |
| 10 | 日期 | 日期 | 便于按天筛选和日报查询 |
| 11 | 实例 | 文本/单选 | `tsja`、`wife` 等 |
| 12 | 微信用户ID | 文本 | `from_user_id` |
| 13 | 记录ID | 文本 | 系统唯一键，不使用摘要做主键 |
| 14 | 主模型 | 文本 | 当前 AI 回复模型 |
| 15 | 摘要模型 | 文本 | 默认 `deepseek-v4-flash` |
| 16 | 同步状态 | 单选 | `pending`、`synced`、`failed` |
| 17 | 错误信息 | 多行文本 | 同步失败时记录 |

说明：

- 摘要仅用于展示，不作为真实主键。
- 真实唯一键建议使用 `实例 + message_id`。
- 如果 `message_id` 不存在，则使用 `实例 + 时间戳 + from_user_id + 内容hash`。
- 附件内容应记录“本轮实际参与 AI 对话的附件文本”，包括本轮刚上传文件和仍在上下文中生效的文件锚点。

## TSJA 配置设计

在 `instances/tsja/config.json` 增加 `feishu_summary` 配置段。

示例：

```json
{
  "feishu_summary": {
    "enabled": true,
    "profile": "cli_aaa83f5fcf229bfc",
    "chatbox_folder_token": "<Chatbox文件夹 token>",
    "base_app_token": "<多维表格 app token>",
    "table_id": "<聊天记录 table id>",
    "daily_report_table_id": "<可选：日报 table id>",
    "daily_doc_token": "<可选：日报云文档 token>",
    "summary_model": "deepseek-v4-flash",
    "summary_max_chars": 20,
    "sync_mode": "async",
    "queue_file": "logs/feishu_summary_queue.jsonl"
  }
}
```

配置原则：

- `enabled` 控制功能开关。
- `profile` 必须显式配置，避免误写入默认飞书账号。
- `chatbox_folder_token` 指向飞书云盘下的 `Chatbox` 文件夹，是多维表格和日报云文档的统一存放目录。
- TSJA 阶段只配置 TSJA 的飞书账号和表格。
- wife 阶段复制同一配置结构，只替换 `profile`、`chatbox_folder_token`、`base_app_token`、`table_id`、日报目标。

## 模块设计

新增目录：

```text
feishu-summary/
  index.js
  config.js
  formatter.js
  summarizer.js
  queue.js
  lark-cli.js
  daily-report.js
```

### index.js

对外暴露主入口：

- `initFeishuSummary(config, runtimeInfo)`
- `recordChatTurn(event)`
- `generateDailyReport(date)`

`bot.js` 只调用入口函数，不直接拼 lark-cli 命令。

### config.js

负责校验 `feishu_summary` 配置。

必须校验：

- `enabled` 是否为 true。
- `profile` 是否存在。
- `chatbox_folder_token` 是否存在。
- `base_app_token` 和 `table_id` 是否存在。
- `summary_model` 是否存在，缺省为 `deepseek-v4-flash`。
- `queue_file` 缺省为 `logs/feishu_summary_queue.jsonl`。

配置不完整时，应禁用飞书汇总并打印明确日志，不影响微信机器人启动。

### formatter.js

负责把一轮聊天事件转换为多维表格字段。

输入：

- instanceName
- fromId
- messageId
- timestamp
- userContent
- attachmentNames
- attachmentText
- aiReply
- model
- usage

输出：

- recordId
- fields

### summarizer.js

负责生成 20 字以内摘要。

摘要输入建议包括：

- 用户内容
- 附件名称
- AI 回复前 500 字

摘要要求：

- 20 个中文字符以内。
- 不要标点堆叠。
- 不要输出引号。
- 不要输出“摘要：”前缀。
- 失败时使用本地兜底摘要：用户内容前 20 字。

### queue.js

负责本地队列和失败重试。

设计要求：

- 每轮聊天先写本地 JSONL 队列，再异步同步飞书。
- 同步成功后记录成功日志。
- 同步失败保留队列项和错误信息。
- 启动时可扫描 `pending` 或 `failed` 项进行重试。
- 队列文件在实例目录下，例如 `instances/tsja/logs/feishu_summary_queue.jsonl`。

### lark-cli.js

负责封装 `lark-cli` 调用。

要求：

- 所有命令必须显式带 `--profile`。
- 使用 `child_process.spawn` 或 `execFile`，避免 shell 注入。
- 参数使用数组传递，不拼接 shell 字符串。
- 捕获 stdout、stderr、exit code。
- 对飞书限流或网络失败做可重试错误标记。

### daily-report.js

负责每日简报。

第一版可从本地队列或当天已同步记录生成日报，避免过早依赖飞书查询接口。

日报内容建议：

- 今日总对话数。
- 今日 token 消耗。
- 主要话题。
- 重要结论。
- 待办事项。
- 异常或失败记录。
- 涉及附件的对话摘要。

## bot.js 接入点

主要接入 `sendAiReply()`。

当前流程：

```text
获取 history
调用 callAI()
更新 dailyStats
addToHistory()
写入文件锚点
发送 AI 回复
```

目标流程：

```text
获取 history
整理本轮附件上下文
调用 callAI()
获得 reply 和 usage
更新 dailyStats
addToHistory()
写入文件锚点
异步 recordChatTurn()
发送 AI 回复
```

注意：

- 飞书同步不能阻塞微信回复。
- 飞书同步失败不能影响 AI 回复发送。
- 需要保证用户内容、附件内容、AI 回复和 token 都来自同一轮。

## callAI 改造

当前 `callAI()` 返回字符串。为了记录单轮 token，需要改为返回结构化结果。

建议新增兼容函数或直接改造：

```js
{
  text: "AI 回复内容",
  usage: {
    inputTokens: 123,
    outputTokens: 456
  }
}
```

`sendAiReply()` 中再使用：

```js
const aiResult = await callAI(userContent, botConfig, history);
const reply = aiResult.text;
```

失败兜底时也返回结构化结果：

```js
{
  text: "AI 接口暂时不可用，请稍后再试。",
  usage: {
    inputTokens: 0,
    outputTokens: 0
  }
}
```

## 附件内容策略

需要区分三种情况：

1. 用户只发文本，无附件。
2. 用户先发文件，再发指令，文件内容和指令一起进入 AI。
3. 用户后续继续追问，历史文件锚点仍参与 AI。

字段写入规则：

- `附件名称`：记录本轮参与上下文的文件名。
- `附件内容`：记录本轮参与上下文的解析文字。
- 如果多个附件参与，用清晰分隔符拼接：

```text
--- 文件: xxx.pdf ---
解析文字...

--- 文件: yyy.docx ---
解析文字...
```

为了避免多维表格字段过大，第一版建议：

- 单条附件内容最多写入 20000 字。
- 超出部分截断并追加提示。
- 原始完整内容仍保留在现有日志或后续独立附件归档方案中。

## 每日 20:00 简报

现有 `scheduler.js` 已支持 `20:00 daily_report`。建议新增任务类型：

```json
{
  "time": "20:00",
  "action": "feishu_daily_summary"
}
```

TSJA 配置初期可以同时保留原有 `daily_report`，但建议最终把微信内日报和飞书日报拆开。

日报生成流程：

1. 读取当天本实例聊天记录。
2. 统计对话数、token、附件数量、失败同步数。
3. 调用 Deepseek 生成日报正文。
4. 写入飞书日报目标。
5. 记录日报生成状态。

日报生成失败时：

- 不影响机器人运行。
- 写错误日志。
- 保留当天原始记录，允许手动重跑。

## 开发阶段

### 阶段 1：TSJA 单实例写入多维表格

目标：

- `tsja` 每轮聊天可以写入多维表格。
- 字段顺序符合要求。
- 摘要、时间、用户内容、AI回复内容排在前四列。
- 飞书失败不影响微信回复。

交付：

- `feishu-summary` 基础模块。
- `config.json` 配置读取。
- 单轮记录格式化。
- lark-cli 写入多维表格。
- 本地队列日志。

### 阶段 2：摘要和 token 完整化

目标：

- Deepseek-v4-flash 生成 20 字以内摘要。
- 每条记录包含 input/output/total token。
- 摘要生成失败有兜底。

交付：

- `callAI()` 结构化返回 usage。
- `summarizer.js`。
- 摘要字段写入。

### 阶段 3：附件内容接入

目标：

- 文件解析文字进入 `附件内容` 字段。
- 后续追问如果仍引用文件锚点，也能写入附件字段。

交付：

- 附件上下文收集函数。
- 附件内容截断策略。
- 多附件格式化。

### 阶段 4：每日 20:00 简报

目标：

- 每天 20:00 对当天 TSJA 聊天生成日报。
- 日报由 Deepseek 生成。
- 日报云文档创建或更新在 TSJA 飞书云盘的 `Chatbox` 文件夹下。
- 支持失败重试或手动重跑。

交付：

- `feishu_daily_summary` 调度任务。
- `daily-report.js`。
- 日报写入目标。

### 阶段 5：复制到 wife

目标：

- 不改代码，只改 `instances/wife/config.json`。
- wife 使用自己的飞书 profile 和表格。

交付：

- wife profile 授权文档。
- wife 配置模板。
- wife 单实例验证记录。

## 风险和控制

| 风险 | 控制方式 |
|---|---|
| 飞书接口失败影响微信回复 | 飞书同步异步执行，失败只记日志 |
| 写错飞书账号 | 所有命令强制显式 `--profile` |
| 摘要重复 | 摘要只做展示，记录ID做唯一键 |
| lark-cli 输出或参数变化 | 封装在 `lark-cli.js`，集中处理 |
| 附件内容过长 | 字段截断，保留提示 |
| token 记录不准确 | 改造 `callAI()` 返回单轮 usage |
| 日报生成失败 | 原始记录已保留，可重跑 |
| 多实例互相污染 | 队列文件、配置、profile 均实例隔离 |

## 完成标准

TSJA MVP 完成标准：

- 发送普通文本消息后，多维表格新增一条记录。
- 前四列顺序为：摘要、时间、用户内容、AI回复内容。
- 摘要不超过 20 字。
- 用户内容和 AI 回复内容准确对应同一轮。
- input/output/total token 正确写入。
- 文件对话可以写入附件名称和附件内容。
- 飞书同步失败时微信仍能正常回复。
- 晚上 20:00 可以生成当日简报。
- 重启 PM2 后功能继续可用。

wife 复制完成标准：

- `wife` 使用独立飞书 profile。
- `wife` 写入自己的多维表格。
- `tsja` 和 `wife` 数据不会互相写错。
