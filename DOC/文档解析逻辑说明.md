# 文档与图片解析逻辑说明

本文梳理当前项目里“用户发文件/图片后，机器人如何解析并交给 AI”的完整链路。主要代码位置：

```text
bot.js                    微信机器人主流程
document-service/server.js Node 文档解析服务
ocr-service/main.py       Python OCR 微服务
ocr-demo/                 浏览器 OCR 测试台
instances/*/config.json   每个机器人实例的配置
```

## 1. 总体流程

机器人不是收到文件后立刻让 AI 总结，而是分两步：

```text
用户发送文件或图片
  -> bot 下载并解密微信媒体文件
  -> 文件发送给 document-service 解析成“文本”或“图片”
  -> 暂存在 pendingFiles，默认等待 30 分钟
  -> 用户再发一句要求，例如“总结一下”“提取重点”“图上写了什么”
  -> bot 把文件内容 + 用户要求一起发给 AI
  -> AI 回复
```

这样做的好处是：用户可以先发文件，再明确要求；bot 不会收到文件后盲目消耗模型 token。

暂存超时时间：

```text
PENDING_FILE_TTL_MS = 30 分钟
```

如果超过 30 分钟才发要求，文件内容会被丢弃，只按普通文本对话处理。

## 2. 文件下载与解密

微信文件和图片都仍由 bot 走同一个下载解密函数：

```text
downloadAndDecryptMedia()
```

流程：

```text
读取 media.full_url 或 encrypt_query_param
  -> 从微信 CDN 下载加密内容
  -> 用 aes_key 做 AES-128-ECB 解密
  -> 如有 md5，做 MD5 校验并打印日志
  -> 返回原始文件 buffer
```

文件消息再包一层：

```text
downloadAndDecryptFile()
```

## 3. 支持类型总览

当前主机器人支持：

```text
图片消息：JPEG / PNG / GIF / WebP
文件消息：PDF / DOCX / TXT / XLSX / XLS / PPTX
```

不支持或不完整支持：

```text
DOC 老 Word 格式：不支持，只支持 DOCX
PPT 老格式：不支持，只支持 PPTX
图片里的文字：图片消息本身不走本地 OCR，而是交给 AI vision 看图
PPTX 内图片、复杂图表：当前只提取文本，不做幻灯片截图识别
Excel 公式语义、合并单元格样式：当前转 CSV 文本，样式信息基本丢失
```

## 4. PDF 解析逻辑

PDF 是最复杂的一类，入口已经迁移到：

```text
document-service/server.js -> parsePdf(buffer)
```

核心依赖：

```text
pdfjs-dist          解析 PDF、读取文本层、渲染页面
@napi-rs/canvas     把 PDF 页面渲染为 PNG
ocr-service         对渲染后的 PNG 做 OCR
```

PDF.js 已配置本地解码资源：

```text
node_modules/pdfjs-dist/wasm
```

这样可以处理部分扫描 PDF 使用的 JBIG2/CCITT 黑白压缩图像，避免页面渲染成空白。

### 4.1 3 页以内 PDF

```text
PDF 页数 <= 3
  -> 每页按 scale=2.0 渲染成 PNG
  -> 转 base64 图片
  -> 暂存为 type=image
  -> 用户下一条要求到来时，把这些图片直接发给 AI vision
```

也就是说，3 页以内 PDF 不先做 OCR，而是让后端模型直接看图片。适合图表、版式、扫描件、小文件。

用户会收到类似提示：

```text
已收到「xxx.pdf」（2页），已转换为图片，请告诉我您的要求。
```

### 4.2 超过 3 页 PDF

```text
PDF 页数 > 3
  -> document-service 检查 OCR_SERVICE_URL
  -> 尝试提取 PDF 文本层
  -> 如果文本层 >= 200 字，直接使用文本层，跳过 OCR
  -> 如果文本层不足 200 字，按页渲染 PNG 并调用 OCR 服务
```

文本层阈值：

```text
PDF_TEXT_MIN_CHARS = 200
```

渲染倍率：

```text
PDF_OCR_RENDER_SCALE = 1.35
```

逐页 OCR 流程：

```text
第 1 页 PDF -> PNG -> /ocr/image -> 得到文字
第 2 页 PDF -> PNG -> /ocr/image -> 得到文字
...
拼成：
## 第 1 页
...

## 第 2 页
...
```

这里目前是逐页调用 `/ocr/image`，不是一次性 batch。这样内存压力较小，也方便日志定位具体哪页出问题。

### 4.3 PDF OCR 服务未配置

如果超过 3 页且 document-service 没有配置：

```bash
OCR_SERVICE_URL=http://127.0.0.1:8765
```

机器人会提示：

```text
超过3页的PDF识别功能暂未配置OCR服务。
```

### 4.4 PDF 识别为空

如果 OCR 后全文为空，机器人提示：

```text
但未能识别出文字内容，可能是扫描质量较低或纯图片页面。
```

## 5. 图片消息逻辑

微信图片消息入口：

```text
firstItem.type === 2
```

流程：

```text
下载并解密图片
  -> 根据文件头识别格式
  -> 支持 JPEG / PNG / GIF / WebP
  -> 转 base64
  -> 暂存为 type=image
  -> 等用户下一条要求
  -> 作为 image content block 发给 AI
```

图片消息当前不调用本地 OCR 服务。即使用户问“图上写了什么”，也是把图片交给 AI vision 识别。

暂存内容结构大致是：

```js
{
  type: "image",
  fileName: "图片_时间戳.jpeg",
  images: [{ mediaType: "image/jpeg", base64: "..." }],
  timestamp: Date.now()
}
```

用户下一条文字到来后，发送给 AI 的内容大致是：

```js
[
  {
    type: "image",
    source: {
      type: "base64",
      media_type: "image/jpeg",
      data: "..."
    }
  },
  {
    type: "text",
    text: "[用户上传了: 图片_xxx.jpeg]\n用户的要求"
  }
]
```

## 6. Word / DOCX 逻辑

当前只支持 `.docx`，入口：

```text
extractTextFromFile()
```

依赖：

```text
mammoth
```

流程：

```text
DOCX buffer
  -> mammoth.extractRawText()
  -> 得到纯文本
  -> 暂存为 text
  -> 用户下一条要求到来时，把全文 + 用户要求一起发给 AI
```

特点：

```text
提取正文文字为主
不保留复杂排版
不做图片 OCR
表格可能变成普通文本，结构会弱化
```

## 7. TXT 逻辑

`.txt` 处理最简单：

```text
buffer.toString("utf-8").trim()
```

也就是说默认按 UTF-8 解码。如果 TXT 是 GBK/ANSI 编码，可能出现乱码，目前没有自动编码识别。

## 8. Excel / XLSX / XLS 逻辑

支持扩展名：

```text
.xlsx
.xls
```

依赖：

```text
xlsx
```

流程：

```text
XLSX/XLS buffer
  -> XLSX.read(buffer, { type: "buffer" })
  -> 遍历所有 Sheet
  -> 每个 Sheet 转 CSV
  -> 拼成文本
  -> 暂存为 text
```

拼接格式：

```text
## Sheet: Sheet1

列1,列2,列3
...

## Sheet: Sheet2

...
```

特点：

```text
保留单元格文本和基本表格行列
不保留颜色、字体、边框等样式
合并单元格、公式、筛选、图表等信息可能丢失或弱化
```

## 9. PPTX 逻辑

支持扩展名：

```text
.pptx
```

依赖：

```text
node-pptx-parser
```

流程：

```text
PPTX buffer
  -> 临时写入 logs/tmp_时间戳.pptx
  -> node-pptx-parser 读取文本
  -> 按 slide 拼接
  -> 删除临时文件
  -> 暂存为 text
```

拼接格式：

```text
## Slide 1

第一页文字

## Slide 2

第二页文字
```

特点：

```text
只提取幻灯片里的文本
不渲染幻灯片页面
不识别图片中的文字
不保留视觉版式
复杂 SmartArt、图表、嵌入对象可能提取不完整
```

## 10. OCR 微服务逻辑

OCR 服务目录：

```text
ocr-service/main.py
```

启动后监听：

```text
http://127.0.0.1:8765
```

接口：

```text
GET  /health
POST /ocr/image
POST /ocr/batch
```

核心依赖：

```text
rapidocr-onnxruntime
Pillow
FastAPI
Uvicorn
```

### 10.1 /ocr/image

输入：

```text
multipart/form-data
字段名：file
内容：单张图片
```

流程：

```text
读取文件
  -> Pillow 打开图片
  -> RapidOCR 识别
  -> 返回 text 和 lines
```

返回示例：

```json
{
  "text": "识别出的全文",
  "lines": ["第一行", "第二行"]
}
```

如果传入 PDF 或非图片，会返回 400：

```text
无法识别图片文件，请上传 JPG/PNG/WebP 等图片，PDF 请走 PDF OCR 模式
```

### 10.2 /ocr/batch

输入：

```text
multipart/form-data
字段名：files
内容：多张图片
```

返回：

```json
{
  "pages": [
    { "page": 1, "text": "第一页文字" },
    { "page": 2, "text": "第二页文字" }
  ]
}
```

当前主 bot 的 PDF OCR 走 `/ocr/image` 逐页调用；`/ocr/batch` 主要给测试台或后续批量场景使用。

## 11. OCR Demo 测试台

目录：

```text
ocr-demo/
```

启动：

```bash
cd /opt/weixin-bot-ai/ocr-demo
npm start
```

默认地址：

```text
http://127.0.0.1:8899
```

测试台用途：

```text
单张图片 OCR
多图 batch OCR
PDF 自动：有文本层则跳过 OCR
PDF 只读文本层

```

## 12. 文件内容如何交给 AI

### 12.1 文本类文件

包括：

```text
DOCX / TXT / XLSX / XLS / PPTX / 大 PDF OCR 结果 / 大 PDF 文本层
```

用户下一条要求到来后，bot 拼成：

```text
[用户之前发送了文件: 文件名]

文件全文

[用户要求]
用户刚发的文字
```

然后作为普通文本消息发给 AI。

### 12.2 图片类文件

包括：

```text
微信图片消息
3 页以内 PDF 渲染出的页面图片
```

用户下一条要求到来后，bot 拼成 image content blocks + text content block，发给 AI vision。

## 13. 当前重要限制

```text
1. 只处理每条消息的第一个 item。
2. DOC 不支持，只有 DOCX。
3. PPTX 只抽文字，不看图片和版式。
4. 图片消息不走本地 OCR，而是交给 AI vision。
5. 大 PDF 如果有 200 字以上文本层，会跳过 OCR；如果文本层质量差但超过阈值，可能不会走 OCR。
6. TXT 默认 UTF-8，非 UTF-8 可能乱码。
7. 大文件全文会直接拼给 AI，当前没有做分块摘要或检索。
8. 对话历史会截断到每条 2000 字，但当前这次文件全文仍会直接发给 AI。
```

## 14. 推荐排查方式

PDF 识别异常时：

```text
1. 用 OCR Demo 的 “PDF 强制逐页 OCR” 看页面预览是否空白。
2. 如果预览空白，优先查 PDF.js 渲染或 JBIG2/CCITT 解码。
3. 如果预览正常但 OCR 为空，查扫描质量、清晰度、倾斜、字体大小。
4. 看 ocr-service/logs/err.log 是否有 Pillow 或 RapidOCR 报错。
```

OCR 服务状态：

```bash
curl http://127.0.0.1:8765/health
pm2 status
```

OCR Demo 状态：

```bash
curl http://127.0.0.1:8899/api/health
```

Bot 文件处理日志：

```text
instances/<实例名>/logs/bot.log
instances/<实例名>/logs/bot-error.log
instances/<实例名>/logs/debug_messages.jsonl
```
